# Disposable construction and alternative comparison

A PoC should answer a decision with the smallest useful executable artifact; it does not
need production maintenance structure. For two or more alternatives, hold the relevant
inputs, conditions and evaluation protocol constant. Define what each variant tests and
how the evidence changes the decision. Disclose selection and negative results.

Keep prototype code out of supported production paths unless explicitly productizing it.
Exploration can use scratch work; evidence used for confirmatory claims needs a reliable
record and appropriate confirmation. Do not require every reconnaissance command to be
preregistered or force a new generic harness merely to compare two options.

Converge from the selected behavior and quality contract, not by accumulating all variant
implementations behind flags. A comparative result is not permission to deploy or alter
hardware. Production proof and applicable data/security boundaries still apply.
