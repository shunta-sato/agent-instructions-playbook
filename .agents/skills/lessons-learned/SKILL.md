# Durable learning

Use the observed sequence, artifacts and counterfactual evidence to distinguish an
implementation defect, tool/environment failure, missing context or harmful instruction.
A successful final attempt alone does not establish causality. Ordinary retries or two
different ideas do not automatically require a retrospective.

Retain a reproducing case or regression test before adding general prose. Put a
mechanically preventable recurring failure in the responsible tool/check; project
facts belong with that project, not in every agent's always-on contract. If a skill
change is needed, replace the relevant instruction rather than append an exception.

For uncertain causes, state the missing signal and a meaningful revisit condition.
No generic 'be careful' action, required JSON/report pair, new skill, or automatic
follow-up issue is implied. Use an existing record or a durable report when it has
a real consumer. Compare changes on unrelated tasks before promoting them globally.
