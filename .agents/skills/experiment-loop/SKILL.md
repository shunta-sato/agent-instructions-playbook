# Confirmatory experiments

Use a testable hypothesis, a disconfirm predicate and the actual metric-producing
command. Separate exploratory observations from confirmation, disclose selection and
repeated attempts, and retain negative results. Routine development tests need not be
registered as research experiments.

`references/runner.md` describes the optional bundled project-level research runner.
Use it when the project adopts its ledger; it is not required for every observation.
An existing trustworthy experiment system is also valid. Do not hand-edit runner
stamps, digests or outcomes, alter a registered command in place, or hide failed runs.

A byte-identical replay checks repeatability under the same conditions; it is not an
independent reproduction. A claimed reproduction needs the relevant new axis, such as
seed, data slice, environment or hardware. A disconfirmed hypothesis is useful
research, not a failed run to retry until it becomes favorable.

Report the experiment identity, observed result, interpretation and limits. Confirmatory
claims need evidence matching the stated conditions; a registered ID alone is not proof.
