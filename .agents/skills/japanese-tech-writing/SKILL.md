# Japanese technical writing

Use the intended reader's vocabulary and distinguish observation, inference,
requirement and limitation. Preserve API identifiers, units, version numbers and
commands exactly. Introduce uncommon abbreviations before relying on them.

Prefer concrete subjects and actions over nominalized chains. Keep Japanese and
English terminology consistent across the document; do not transliterate identifiers
or use English merely to sound technical. Separate what was tested from what remains
unknown, and cite the source that supports important factual claims.

Follow the project's existing style when it is explicit. This is not an instruction
to add sections, tables, summaries or translations the user did not ask for.
