# Discover the operating envelope

Distinguish supported operation from a convenient test condition. Identify normal,
peak, sustained, burst and degraded workloads; concurrent components; input sizes,
cadence and lifetime. Include startup, recovery, disconnection and shutdown when they
change the decision. A quiet development target is not a production baseline.

Start from existing requirements, traces, configuration and measurements. Record
confirmed, inferred and unknown facts with their source. A physically separate target
does not by itself imply a particular battery, thermal or timing budget. Unknown power
state is not AC power. Unknown workload is not permission to choose an easy benchmark.

Select the next observation to resolve a decision, not to populate a universal matrix.
Compare multiple plausible envelopes only when they change design or proof. Identify
the consequence of being outside the supported envelope and the actual recovery policy.
Freeze the relevant envelope with an evidence claim; reopen it when use, deployment,
concurrency, target, cadence or continuous runtime changes. Missing target access blocks
the target claim, not independent authorized analysis or host implementation.
