# Instruction maintenance

Retain non-obvious project/domain knowledge and outcome, authority, quality and
evidence boundaries. Remove generic teaching, obsolete model scaffolding, duplicate
routing and mandatory paperwork. A skill should add capability, not certify that a
procedure was followed.

Keep descriptions short and selective. Put a reference behind the decision it
helps, not a mandatory read-all list. Prefer actual scripts/fixtures to prose for
machine-checkable invariants; keep permission enforcement in the execution system.
Model and client configuration belong to the harness, not skill bodies.

Turn a failure into a reproducible evaluation before adding a rule. Compare current
instructions, a minimal contract, and minimal-plus-specialists on matched tasks.
Judge outcomes and evidence, not trigger keywords or self-reported compliance.
Recheck near misses, unnecessary stops and costs as well as defect prevention.

A normal retry or alternate hypothesis is not a mandatory retrospective. Preserve
an existing test, project fact or useful local note before adding a global rule.
When instructions block authorized progress, identify the exact instruction and
blocked action. Replace or remove the cause; do not add an exception stack.

Report static validation separately from actual model runs. Never claim Astra
qualification from a fake adapter or an earlier model's run.
