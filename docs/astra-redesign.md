# Astra-generation redesign

This is an instruction architecture change, not a model-performance claim. It implements
outcome contracts, native selective Skill discovery, conditional specialist references and
mechanical checks of real constraints. There is no second generic delivery super-Skill.

## Four boundaries

- The contributor contract describes this repository only. The consumer template is a
  reusable starting point, not an automatic project-policy overwrite.
- A task carries outcome, scope, authority and relevant quality conditions in its existing
  issue/PR/brief; no new per-task ceremony is required.
- Specialist Skills provide non-obvious knowledge, evidence requirements and optional
  tools/assets. They do not replace the model's ordinary design/debugging ability.
- The actual harness/CI/target enforces execution permissions and runs checks. Instructions
  cannot provide sandboxing or confer approval. Model choice belongs to that harness.

## Deliberate removals

Mandatory delivery routing/final-gate Skills, generated all-Skill index, model-catalog and
role lockfiles, generic design/TDD/readability lesson Skills, fixed rollback counters and
mandatory retrospective/artifact packs are removed. Existing names have no aliases.
`docs/skill-disposition.json` records the disposition of every prior entrypoint.
No automatic project-wide line count, polling threshold or test count remains.

## Retained substantive assets

Context-driven required/target quality distinction; actual target and workload evidence;
controller/target identity and argv boundaries; platform/lifecycle/concurrency constraints;
seven UI style/token families and previews; API-removal sweep; repository/mobile inspectors;
optional research runner, claim/promotion/digest verification and their regression tests.
Historical evidence stays immutable. Preserving its machine schema is not retaining the old
runtime Skill routing. New regression cases take priority over appending general rules.

## Validation and honest limits

`make verify` validates current catalog/links, compiles Python, checks existing ledger
integrity and executes regression tests. Tests of retired procedural schemas were removed
with those schemas; research integrity and supported tool behavior tests remain. New tests
exercise selective installation, collisions, evidence tampering and evaluation outcomes.

Live Astra behavior is **not measured** by these tests. `evals/` provides three instruction
arms, three functional task oracles and six trace-review seeds. Some seeds require supplied
real fixtures before scoring. The runner is not a sandbox; external adapter confinement and
independent behavioral adjudication are required. This branch is suitable for code review,
not a claim of proven Astra superiority, optimal Skill count or production readiness.

## Sources and interpretation

- OpenAI, “Rethinking skills and prompts for GPT-6 Astra”:
  https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra
- OpenAI Skills documentation: https://developers.openai.com/codex/build-skills

The redesign applies selective descriptions/references, fewer routine instructions, scoped
autonomy and explicit completion. It does not infer that fewer tests, no safeguards or
unbounded execution are better. Skill names/counts, installer semantics and task fixtures
are this repository's design choices, not vendor-required settings.
